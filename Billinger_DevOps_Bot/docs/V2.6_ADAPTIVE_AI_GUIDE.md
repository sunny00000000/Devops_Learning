# Billinger Bot v2.8.0 — Adaptive AI Mentor Guide

## Purpose

Version 2.6 adds an optional online intelligence layer to the existing deterministic Billinger learning platform. It personalizes explanations and assessments while preserving the verified curriculum, fixed scoring rules, student separation, and offline fallback.

## Provider responsibilities and fallback

| Task | Default primary | Default fallback chain |
|---|---|---|
| Learning tutor | Gemini | Groq, OpenAI, OpenRouter |
| Test analysis | OpenAI API | Gemini, OpenRouter, Groq |
| Interview analysis | OpenAI API | Gemini, OpenRouter, Groq |
| Question generation | Groq | Gemini, OpenRouter, OpenAI |
| Curriculum audit | Gemini | OpenAI, OpenRouter, Groq |
| Company interview | OpenRouter | OpenAI, Gemini, Groq |
| Resume/portfolio review | OpenAI API | Gemini, OpenRouter, Groq |

Routes are defaults, not hard-coded restrictions. Administrators can reorder enabled providers independently for every task.

## Automatic failover sequence

1. Read the selected task route.
2. Skip providers that are disabled, unconfigured, cooling down, or over their local daily limit.
3. Send the redacted task to the first eligible provider.
4. On quota/credit/rate-limit, timeout/network, temporary server failure, invalid JSON, or empty output, record the failure and try the next provider.
5. Return the first successful response with its provider, model, duration, and fallback trace.
6. When every provider is unavailable, use the verified local question bank where that workflow supports a local fallback; otherwise return a clear availability error without losing student data.

Administrators may disable automatic failover for controlled provider testing.

## Adaptive test analysis

AI test analysis can identify:

- strong and weak domains;
- recurring misconceptions;
- missing commands or configuration concepts;
- diagnostic, security, evidence, and rollback gaps;
- a targeted revision plan;
- recommended follow-up labs and retests.

The original numeric test score remains authoritative. AI cannot silently change a pass into a fail or a fail into a pass.

## Interview analysis

Written interview answers can be reviewed for technical accuracy, troubleshooting sequence, validation evidence, security, rollback, communication, and business impact. The fixed interview engine continues to decide progression. AI feedback is displayed as an advisory analysis with provider/model metadata.

## Curriculum-gap auditor

Administrators may request an audit by domain, command group, job role, or supplied context. The result is saved as a review proposal. It cannot automatically edit lessons, publish internet claims, or reclassify uploaded course books. An administrator must verify product versions and authoritative sources before accepting a proposal.

## Adaptive question modes

- Adaptive weakness test
- Balanced random test
- Command-focused test
- Incident/troubleshooting test
- Company-role test

When online generation fails, Billinger selects appropriate questions from its verified local bank and labels the session `local_fallback`.

## Privacy controls

- Provider keys are entered only after administrator authentication.
- Windows installations use DPAPI encryption tied to the Windows user.
- Keys are never returned by the API or included in normal JSON backups.
- Common email addresses, telephone numbers, API keys, tokens, and private-key material can be redacted before online requests.
- Administrators can disable student-content submission to online providers.
- Every provider call is logged without storing the API key.

## Operational boundaries

Online responses can be incomplete or incorrect. Treat AI output as a learning aid, verify current commands against authoritative documentation, and never execute unfamiliar or destructive commands on production systems. The existing Safe Real Lab restrictions remain in force.
