# Billinger Bot v2.7.0 — Final Readiness Guide

## Purpose

Version 2.7 freezes major feature expansion and adds the acceptance controls needed before students begin regular learning. It does not claim that a course alone creates mastery. It verifies setup, establishes a starting level, protects progress, distinguishes simulations from real execution, and requires evidence across learning, practical work, company scenarios, interviews, and portfolio projects.

## First-run sequence

1. **Administrator setup** — protects provider credentials, course freshness records, imports, backups, and institute controls.
2. **Learner goal** — selects the target role and available daily study time.
3. **Baseline** — 20 multiple-choice questions across Linux, networking, Git, shell, Docker, Kubernetes, Terraform, DevSecOps, SRE, and system design.
4. **Verified library** — confirms classified PDF/DOCX resources are available.
5. **Environment scan** — executes only fixed, read-only version checks for Python, Git, WSL, Docker, kubectl, Terraform, Ansible, AWS CLI, Azure CLI, and Google Cloud CLI.
6. **AI health** — optional. A student can start without any online AI provider.
7. **Backup** — verifies the latest recorded backup by streaming SHA-256 comparison and ZIP integrity testing.
8. **Daily plan** — generates the first personalized study sequence.

Only required steps control the learning launch gate. Environment tools and online AI are optional.

## Baseline interpretation

The baseline classifies the current starting point as:

- Complete beginner
- Foundation learner
- Junior-ready learner
- Intermediate learner
- Advanced learner

The baseline recommends a starting focus but does not waive mastery requirements. A high baseline score does not automatically complete lessons, projects, incidents, or interviews.

## Practice labels

- **Guided learning** — verified explanations and worked examples.
- **Safe simulation** — evaluates reasoning and evidence without changing the host.
- **Real local execution** — uses an installed tool in a controlled workspace.
- **External cloud lab** — requires a separately controlled account, budget, and authorization.
- **Simulated company scenario** — ticket, incident, review, communication, and business-impact practice.

## Mastery gates

Every domain requires all nine evidence categories:

| Gate | Required evidence |
|---|---|
| Lessons | All lessons completed |
| Guided labs | All labs passed |
| Knowledge test | 85% or higher |
| Practical exams | Four levels at 80% or higher |
| Company tickets | Every assigned domain ticket passed |
| Incident | 78% or higher |
| Capstone | 82% or higher |
| Interview | 80% or higher |
| Portfolio | Approved evidence at 80% or higher |

## AI model discovery

After saving a provider key, the administrator can query the provider’s model-list endpoint and cache the returned identifiers locally. Discovery does not guarantee that every returned model supports every Billinger task, so each selected model must still pass **Test connection**.

The fallback dry run evaluates configuration, local daily limits, cooldowns, and simulated provider failures without sending an external request or consuming credits.

## Course freshness

Each DevOps domain records:

- Billinger course version
- Tool/version coverage description
- Official documentation URL
- Last reviewed date
- Current, review due, review required, or deprecated status
- Deprecation/migration notes
- Reviewer identity

AI curriculum proposals remain `review_required` until an administrator checks official documentation and approves the change.
